## 0. 一句话结论

烬的标题页**不是"构图差"，是"信息量过大 + 字标太小"**：背景层数已经够（5–6 层），但各层明暗差只有 3–15 阶，全部糊成一片；字标只占屏幕面积 **0.64%**，而首屏可点元素超过 20 个。参照作品的做法几乎全部相反：**背景只做一件事，字标独占最大对比，首屏不超过 4 个可点项**。

## 3. 五条可落地规律（每条给参数）

### R1 · 焦点唯一，且位置不随内容漂移
- 参数：全屏只允许 **1 个"最大对比块"**（字标）；字标光学中心落在屏幕高 **36%–46%**；主 CTA 底边落在 **78%–86%**；两者垂直间距 ≥ **25% 屏高**；**内容增减不得改变字标的 y 坐标**。
- 来源：Hades 把菜单压到左侧、把整块画面让给美术【源】；分区式布局（上中下三带）在行业文章中被反复提到【源，权威性一般】；Minecraft logo 独占【源】。"36–46% / 78–86% / ≥25%"是我按上述结构折算的工程值【推】。

### R2 · 同屏字号 ≤4 档，相邻档 ≥1.5×，主副 ≥2.5:1，中文 ≥12px
- 参数：字标 : 副标 ≥ **2.5:1**；相邻两档 ≥ **1.5×**（避免 9/10/11/12 挤成"看起来一样大"）；同屏 ≤ **4 档**（含 CTA）；中文最小 **12px**、等宽角标最小 11px。
- 来源：游戏 UI 图形设计原则研究——层级靠 size / weight / case / spacing 区分，正文显著小于标题【源：[thinkmind 论文](https://ns2.thinkmind.org/articles/visual_2022_1_20_70008.pdf)】；"中文 12px 下限"是烬自己的 [03-SPEC §2](file:///D:/其他/TRAE宝/奥术工程师/ui-audit/03-SPEC.md) 已定下的规矩【源：文件】。

### R3 · 背景 ≥3 层，层间明度差 ≥20 阶，文字区不许有高频细节
- 参数：至少 3 层（底 / 中景 / 前景主体）；相邻层明度差 ≥ **20**（0–255 的 L 分量）；字标外接框向外扩 **1.2 倍字高** 的范围内，装饰线 opacity ≤ **0.08** 或加径向遮罩；装饰线宽 ≤ **1.5px** 且不得与字标笔画同方向密集出现。
- 来源：Balatro 的扫描线"始终存在但很淡"、且菜单/商店/暂停维持同一套视觉【源】；Hades 把整块画面让给美术而不是叠装饰【源】。"≥20 阶 / op≤0.08 / 1.2 倍字高"是工程阈值【推】，理由是低于 20 阶的两层在深底（L≈8–20）上肉眼会读成一层——这一点被烬自己的实测数据支持（见 §4 V3）。

### R4 · 同一时刻运动源 ≤2 个；动的是背景/品牌，不是内容
- 参数：常驻运动源 ≤ **2**；背景/运镜周期 **8–20s**（不能让人看出循环接缝）；文字进场一次性 **0.6–1.0s**；禁止常驻文字抖动/呼吸/发光脉动；品牌字标允许"自身形变"（如 CRT 扭曲）但幅度需 ≤ **2%**。
- 来源：Hades 重做 logo 与 menu animation【源】；Persona 5 焦点随选项切换而非常驻乱动【源】；Mega Man X4 的时序"闪光 → 角色冲入 → logo 与背景揭开"【源】；Balatro logo 自身形变【源】。数值区间为经验值【推】。

### R5 · 首屏可点元素 ≤4 个，其余收进二级面板
- 参数：首屏 ≤ **4** 个可点（建议：开始 / 继续 / 设置 / 更多）；次级入口用**同区域一档小字链或图标行**，不并排铺开；危险操作（覆盖存档）不与主 CTA 同色；主/次对比靠"尺寸 + 描边亮度"，不靠加新颜色。
- 来源：Hades 主菜单只有 4 项 + 底部一行图标【源】；Minecraft 标题屏是单层菜单【源】；"主次用对比说、危险用冷暖说"【源：[游戏 UI 结构设计](https://www.163.com/dy/article/I1FLGP9R0526DPBA.html)】。

对应判违规：

- **V1 违反 R1（焦点）**：字标只占屏面积 0.64%，而背景里一个徽记环就画到 `clamp(150px, 26vh, 240px)`、opacity 0.78——**装饰的视觉重量超过标题本身**。更糟的是外壳 `.title-card-v8` 用 `justify-content:center` + `height:100%`，内容一变（"继续上次"出现、天赋多一级、种子记录多一条、展开存档槽）**字标就整体上下漂移**，标题位置不是常量。【源：代码】
- **V2 违反 R2（字号）**：8 档字号、其中 4 档挤在 9–14px 之间（相邻差 1.11–1.16 倍，远低于 1.5×），等于"四个看起来一样大的小字"；9px 中文直接违反烬自己 03-SPEC §2 的 12px 下限。【源：代码 + 03-SPEC】
- **V3 违反 R3（背景层）**：层数够，但**明度差只有 3–15 阶**，不到 20 阶 → 五层读成一层"淡淡的光晕"，这就是"糊、发灰、没高级感"的机制原因。另外徽记容器 `top:26%`、直径最大 240px，而 hero 区块在居中布局里从约 30% 高起——**装饰环几何上必然压在字标区域**，违反"文字背后不许高频细节"。【源：代码 + 几何换算【推】】
- **V4 违反 R4（动效）**：一个 rAF 里同时跑 ≥6 个运动源，且全部压在标题后面；字标本身只有静态 text-shadow，动效没有服务"品牌"。【源：代码】
- **V5 违反 R5（可点数量）**：首屏 ≥20 个可点项，标题页被当成"主菜单 + 设置 + 天赋 + 种子 + 存档"的总控台。【源：代码】

额外一条与构图无关但会毁掉"高级感"的矛盾：**同一个字标在三处是三个颜色**——线上金色（`--gold`）、对照页紫色（`#b085ff`）、03-SPEC 说应该是 `--text-1`。三份文档三个答案，玩家看到的是金色。【源：两份文件】

> 顺带：03-SPEC 的 **B1（字标 104 → 64px）建议不要执行**。本报告的结论是"字标要更大、更稳、背景要更淡"，把它缩到 64px 会让 0.64% 变成 0.38%。【推，依据 §2 的八作共性】

## 5. 最小改动清单（4 处，按收益排序）

只改 4 处，不动整体结构，收益最大：

**M1 · 把 hero 从居中流里"拆出来"，固定位置 + 放大（收益最大）**
- 做法：`.title-hero` 改 `position:absolute; left:0; right:0; top:38%; transform:translateY(-50%)`；字标 `font-size: clamp(72px, 18vh, 168px)`；下方补一行英文副标 `EMBERFALL`（26px，字距 0.30em），让"字标组"横向占到屏宽 **≈22%**、面积从 0.64% 提到 **≈2.4%**【推：168×205 + 副标 26×200 的组合框】。
- 为什么：一次同时修掉 V1（面积 + 位置漂移）。单字汉字没法靠"占屏宽 40%"取胜（那要 700px 字号），所以要靠"汉字 + 英文副标 + 法阵框"组成一个**块**来堆视觉重量。【推】
- 影响面：只动 `.title-hero` / `.title-wordmark` 两条规则 + 加一行 DOM。

**M2 · 首屏只留 4 个可点，其余整体搬进"更多"**
- 做法：首屏留 `开始探索 / 继续上次 / 设置 / 更多`；把难度、动效声音、永久天赋、挑战、武器、种子、说明/图鉴/存档**原样**塞进一个现有模态（`.rules-layer` 已有 z-index 70 的"压在标题页之上"能力，直接复用）。难度/挑战这类高频项可降级为一行小字链（12px）。
- 为什么：修 V5，同时把首屏字号档数从 8 降到 4（顺带修 V2 的一半），标题页终于"只讲一件事"。【源：Hades 4 项 + 图标行】
- 风险：老玩家多点一次才换难度——用 Enter 直接开始、上次难度记忆可抵消。

**M3 · 背景"减两层、拉开 20 阶"**
- 做法：星点 α 上限 0.42 → **0.24**；微粒 α 0.40 → **0.20**；背景双环 α 0.20/0.14 → **0.10/0.07**；徽记 `top:26%` → **62%**（或给徽记加 `mask-image: radial-gradient(closest-side, transparent 55%, #000 72%)` 把中心掏空，让环不压在字上）；底色保持 `#03070d`，中景提到 `#0d1c2b`，使底/中景差 ≥ **20 阶**。
- 为什么：修 V3 + V4 的"动效压字"。这一步**不加任何新元素**，只压暗、只挪位，所以不会更像"花哨"，只会更像"干净"。【推】
- 影响面：`drawTitleBackground` 里的 4 个 alpha 常量 + 一条 CSS。

**M4 · 字号收敛到 4 档 + 9px 中文全提到 12px**
- 做法：`168 / 22 / 14 / 12`；统计标签 9 → **12**（等宽可 11）；难度副行 9 → **12**；天赋行 9 → **12**；kicker 9–11 → **12**、字距 0.30em → **0.18em**（字距过大在 12px 下会让整行"散架"）。
- 为什么：修 V2 剩余部分 + 直接命中 03-SPEC 自己的硬约束；4 档之后"上下层级"才读得出来。【源：thinkmind + 03-SPEC】

**M5（可选，5 秒改完）· 修颜色矛盾**
- 做法：删掉被覆盖的两条 `.title-layer` radial，或把其中紫色一条真正生效（`#titleLayer` 里加 `radial-gradient(900px 540px at 50% 68%, rgba(176,133,255,.10), transparent 65%)`）；词标颜色定一种——建议**紫**（对应"魔法紫"定位，金色只留给"奥术结晶"数字）。
- 为什么：现在"深蓝 + 科技青 + 魔法紫"里的**紫根本没有渲染**，等于品牌色少一档；而三份文档三个颜色会让后续所有评审互相打架。【源：两份文件】

> 若只能改一处：**改 M1**。它单独就能把"标题是配角、光晕是主角"这个最伤的问题翻过来。
