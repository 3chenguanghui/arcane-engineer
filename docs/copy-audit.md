### 先给三条最该改的

1. **武器残留文案（违反"纯魔法、无武器"设定）** —— 不是模型问题，是文案还在。`Q 近战` 仍显示在 HUD 键位条与帮助面板，手柄连接提示写 `Y 近战`，卡牌写 `近战与新手优先`，事件选项叫 `祝福 · 锋刃协议`。玩家第一分钟就会问"近战在哪"。
2. **设置页里露出开发过程** —— `素材化（A+C）阶段`、`关闭后 Q 完全无响应…`（描述一个玩家看不到的开关）、`初始奥能上限 +N`。这三条是最像"没做完"的。
3. **奥能与蓝量混用 + 最佳楼层/最高楼层混用** —— HUD 写「奥能」，卡牌写「高蓝量/没蓝」；标题页写「最佳楼层」，设置档案写「最高楼层」。都是同一个数，玩家对照两个界面就会发现。

### 明确可以不管的

- **中英混排空格**：241 条中英/数字混排全部带空格（`生命 HP`、`第 1 层`、`奥能 AETHER`），风格统一，不用动。
- **半角标点**：面向玩家文案里全角逗号/冒号/分号/问号混用 **0 处**。
- **省略号**：仅 2 处，均为单个 `…`，写法正确；无 `...`、无 `。。。`。
- **感叹号叠用**：0 处。
- **层 / 关 / 波**：`层` 175 次是唯一进度单位；`关` 75 次几乎全是「关闭/开关」，`波` 10 次全是「震波/波动」；**不存在关卡口径分裂**。
- **精英 / 首领 / BOSS**：玩家文案只用「精英」43 次、「首领」57 次，`BOSS` 出现 0 次（只存在于代码标识符），**口径统一**。
- **静态默认值 `成就 0 / 8`、`已发现配方 0 / 13`**：`renderArchive()` 运行时会用真实总数覆盖，不是硬编码错误。

## 二、逐条展开

### 类别 1：错别字与病句

#### 1.1 `近战与新手优先` —— 系统已下线，文案还在
- **锚点**：`RELIC_CONFIG` → `{ id: 'hp', name: '强化机体' }` 的 `desc` 与 `impact`
- **上下文**：`最大生命 +15，并立刻回复 15——把"一次失误就死"变成"还能挨两下"，近战与新手优先。`
- **原文**：`近战与新手优先`
- **建议**：`新手与贴脸打法优先`
- **理由**：武器系统已被 `WEAPON_CONFIG.enabled = false` 代码级关闭（标题武器行、HUD 武器条、设置里的「近战武器（Q）」行都由 JS 隐藏）。此处仍把"近战"当成一种可选打法，玩家找不到对应操作。
- **严重度**：**高**（2 处：`desc` 与 `impact` 各一）

#### 1.2 `初始奥能上限 +N` —— 占位符直接暴露给玩家
- **锚点**：`#archiveNote`（`<div class="setting-note" id="archiveNote">`）
- **原文**：`成就只发一次；奖励写入存档并在下一局开局生效（初始奥能上限 +N，或起手多一张卡）。`
- **建议**：`成就只发一次；奖励写入存档并在下一局开局生效（永久提高初始奥能上限，或起手多一张卡）。`
- **理由**：全文检索 `archiveNote` 只有 DOM 声明，没有任何一处运行时赋值；`archiveAchText`、`archiveRecipes` 都有 `renderArchive()` 覆盖，唯独这条没有。`+N` 会原样显示。另与成就面板"显示实际到手值"的既有口径冲突。
- **严重度**：**高**

#### 1.3 `素材化（A+C）阶段` —— 开发排期写进玩家设置页
- **锚点**：设置页「全屏后期 / POSTFX」段的 `.setting-note`
- **原文**：`WebGL 光晕与体积光会在素材化（A+C）阶段接入，届时复用同一个开关。`
- **建议**：删除该句；如要保留预期，改为 `更多后期效果会陆续接入，届时复用同一个开关。`
- **理由**：`A+C` 是内部批次代号（源码里 `M3 素材化` 等注释才用这个说法），玩家无法理解，且等于公开承认"还没做完"。
- **严重度**：**高**

#### 1.4 `关闭后 Q 完全无响应…` —— 描述一个玩家看不到的开关
- **锚点**：`#weaponSettingNote`
- **原文**：`关闭后 Q 完全无响应、标题武器行隐藏、HUD 武器条隐藏；再打开会恢复同一把武器与已装配改造。近战不耗奥能，也不吃元素附着，和魔法 / 装置互不干扰。`
- **建议**：整段删除（随 `#weaponSettingRow` 一起，二者已由 `renderWeaponSettings()` 在 `WEAPON_CONFIG.enabled = false` 时 `hidden`）
- **理由**：该行在正式包中永远不可见，保留只会给后续维护者误判"武器还在"。`无响应` 也是机器视角措辞，不是玩家语言。
- **严重度**：中（不可见，但污染维护判断）

#### 1.5 `朝向 ±25° 内` —— 搭配不当
- **锚点**：`#aimNote`（瞄准辅助说明）
- **原文**：`弱辅助：朝向 ±25° 内、距离 440px 内的敌人会把弹道向它偏转 60%，命中半径放宽 20%`
- **建议**：`弱辅助：在朝向 ±25° 范围内、距离 440px 内的敌人，会把弹道向它偏转 60%，命中半径放宽 20%`
- **理由**：`朝向 ±25° 内` 缺介词，读起来像"敌人位于朝向里"。另"偏转 60%"用百分比修饰角度，语义可疑——**待确认**是否为 `60% 的角度`，确认前不要改数值。
- **严重度**：低（病句）／待确认（口径）

#### 1.6 `两项都写入永久存档` —— 搭配不当
- **锚点**：无障碍设置段 `.setting-note`（`#reduceShake` / `#reduceFlash` 说明）
- **原文**：`两项都写入永久存档，对光敏感 / 容易晕的玩家可长期开启。`
- **建议**：`两项都会永久保存，对光敏感 / 容易晕的玩家可长期开启。`
- **理由**：「存档」是局内存档（`局内存档 · RUN SAVE`）的专有名词，设置项并没有"写入存档"，容易与三槽存档混淆。
- **严重度**：低

#### 1.7 `其它` —— 旧写法
- **锚点**：`P1_KIND_LABEL.other`（死亡归因）与 `HIT_FX_FAMILY.fallback`（受击反馈兜底）
- **原文**：`other: { name: '其它' … }`
- **建议**：`其他`
- **理由**：现代规范用「其他」；且死亡总结里会直接展示这一项。全文 `其它` 21 次，但仅这 3 处是玩家可见标签（另有图鉴分组标签 `'其它卡 / 连锁'`），**不可全局替换**（其余在注释里）。
- **严重度**：低

#### 1.8 `偏转 60%` / `命中半径放宽 20%` —— 单位口径不统一（与 5.2 关联）
- **锚点**：`#aimNote`
- **说明**：同一句里"角度用 %、半径用 %"，而卡片文案里半径写作绝对数（`半径 92`）。建议角度类写"度"、半径类统一写"%"或不写。
- **严重度**：低／**待确认**（牵涉实际手感数值，先不改）

#### 2.1 奥能 vs 蓝量 / 高蓝 / 没蓝
- **锚点 A**：`RELIC_CONFIG` → `{ id: 'overflow', name: '溢流' }` 的 `desc` 与 `impact`
  - 原文：`奥能高于 75% 时技能伤害 +22%——要求维持高蓝量，频繁放技能会熄火。`
  - 原文：`要求维持高蓝量；频繁放技能会熄火，适合低耗高回构筑。`
- **锚点 B**：`CODEX` 资源类条目 `label: '资源 · 高蓝'`
- **锚点 C**：图鉴·吸能体 `intent`：`逼玩家在"没蓝"和"被围"之间做取舍`

- **理由**：同一统计项在标题页与设置档案页叫法不同，玩家会以为是两个指标。

### 类别 4：署名与 CSS 变量

#### 4.1 「陈光辉 制作」的落点与写法
- **唯一真源**：`GAME_CONFIG.author: '陈光辉 制作'`
- **渲染落点（3 处，全部走同一变量）**
  1. 标题页角落 `#titleAuthor`
  2. 关于面板 `#aboutAuthor`
  3. 设置页脚 `#settingsAuthor`（`.settings-author`）
- **结论**：写法**完全一致**（单一数据源，不会出现两种写法）；但与需求里写的规范「陈光辉制作」**差一个空格**。
- **建议**：`'陈光辉 制作'` → `'陈光辉制作'`（若"陈光辉 · 制作"是有意排版则**待确认**）
- **严重度**：低

#### 4.2 `var(--text-4)` 引用了不存在的变量（**已核实**）
- **原文**：`:root` 只定义了 `--text-1 / --text-2 / --text-3`，**没有 `--text-4`**
- **引用处（3 处，2 个选择器）**
  - `.settings-author, .setting-author { … color: var(--text-4); … }`（标题页角落、关于面板、设置页脚共用）
  - `.wb-note { … color: var(--text-4); … }`
  - `.wb-weapon { … color: var(--text-4); … }`
- **真实后果（纠正前提）**：`--text-4` 未定义且**没有写 fallback**，`color` 声明会在"计算值阶段失效"→ 该属性**回退为继承值**，不是整条规则被删、更不是文字消失。所以署名**会显示**，只是颜色变成外层面板的正文色（`--text-2` 一档），比设计意图更亮、更抢眼。
- **建议**：在 `:root` 的文本色层级里补一行 `--text-4: #8ea6c2;`（或直接改为 `color: var(--text-3)`）。**不要**只删掉引用，否则署名与正文同色更难区分。
- **严重度**：中（可见但不符合设计意图）

#### 4.3 `.wb-note` / `.wb-weapon` 的 `--text-4`（同上，但实际不可见）
- **锚点**：`.tree-weapon-bridge` 容器 `#treeWeaponBridge`
- **事实**：全文只有 `ui.treeWeaponBridge = document.getElementById('treeWeaponBridge')` 一处引用，**从未被填充内容**；CSS 又有 `.tree-weapon-bridge:empty { display:none }`。
- **结论**：这两个选择器是死代码，`--text-4` 在此处不影响任何可见像素。修 `--text-4` 时顺手覆盖即可，不必单独处理。
- **严重度**：低

#### 4.4 `--accent` / `--ui-card-r` 引用了未声明变量（有 fallback，不破图）
- **`--accent`**：`.engrave-item` 里 `var(--accent, #5ee1b4)`，2 处。项目实际定义的是 `--acc`（由奖励卡内联 `style="--acc:…"` 注入），疑似拼写遗留；因为有 fallback，画面不会坏，但永远拿不到家族色。
- **`--ui-card-r`**：`.arc-card` 里 `var(--ui-card-r, …)`，2 处。源码注释写明"对比截图通过 `--ui-card-r` 变量回退到 11px"——即它本来就是一个"只在对比时手动注入"的调试变量，缺声明是设计行为。
- **建议**：`--accent` 改为 `--acc`（或在 `:root` 补声明）；`--ui-card-r` 保留，建议在该注释处补一句"默认走 fallback"。
- **严重度**：低

#### 4.5 误报排除
- `var(--xxx)` 出现在 CSS 注释里的"规则示例"，不是真实引用，**不计入**。
- 标题页角落 `#titleAuthor` 的颜色来自 `.title-corner`，不受 `--text-4` 影响（只有关于面板与设置页脚受影响）。
