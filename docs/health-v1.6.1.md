2. **`installDebugApi` 改为按需安装**（`?debug=1` 才装）——可少解析 355,543 字节（JS 的 14.4%），但**必须先核对 `tools/` 里的调用方**，否则测试全线红。
3. **删除 16 个零引用项 + 22 个无引用 CSS 类**（合计 16,184 字节，0.60%）——风险低但要跑核心回归；建议一次只删一类（先函数、再 CSS）。
4. **把 5 份 `setFloor`、2 份 `setAscension`、2 份 `find` 并成 1 份**（785 字节，收益可忽略，纯可读性）。

### 3.2 不建议动（红线）

1. **数值曲线相关代码**：v1.6.1 已验证过的平衡/成长/掉落曲线常量，以及 `applyReward`、`applyRoomReward`、`damageEnemy`、`killEnemy`、`damagePlayer`、`castSlot` 里的数值分支——本轮**一个数字都不动**（这几个函数的存在与位置已核对，但因文件漂移，报告不列行号）。
2. **种子派生与随机流**：`generateFloor` / `spawnEnemiesForFloor` 内的布局、敌人种类、掉落派生链。任何「顺手优化」都会破坏同种子同局承诺。
3. **`generateFloor` 的房间布局与保底规则**（L21,066，294 行，31 个数组字面量）——那是布图概率的核心，不是重复代码。
4. **`installDebugApi` 不能删**：仅可拆/可延迟安装。它对外暴露 267 个顶层键、3,472 个成员，是 `tools/` 下自动化测试的调用面，删掉等于拆测试地基。
5. **`game` / `mapCanvas` 分辨率与绘制节奏**：已验收的视觉基线，动它等于重做验收。

## 4. 最该修的 3 件事 / 最不该动的 3 件事

**最该修**
1. `titleBg` 全尺寸画布常驻 —— dpr1 4.82 MB / dpr2 19.28 MB 纯浪费。

3. `installDebugApi` 的整体存续（只允许拆/延迟，不允许删）。

## 5. 方法与复现

- **静态**：`acorn` 解析 57,428 行内联 JS（0 条语法错误），AST 引用计数 + 整词全文计数 + 字符串字面量动态派发检查；CSS 用规则切分 + 类 token 交叉比对。
- **动态**：无头 Edge + CDP，`Page.addScriptToEvaluateOnNewDocument` 预注入探针（记录 `readystatechange` / rAF / 标题画布首像素），`Performance.getMetrics` 取脚本、布局、堆、节点、监听器；`DOMParser` 微基准测纯 HTML 解析。
- **临时脚本**在 `%TEMP%\arcane_health\`（`analyze2.js`、`verify.js`、`csslive.js`、`numbers.js`、`measure2.js`、`runtime.js`），**不属于交付物**，未写入项目目录。
- **复现要点**：先冻结 MD5 → 跑 `analyze2.js` 得结构与引用 → 跑 `verify.js` 得取证行号 → 跑 `measure2.js` 得首屏 → 跑 `runtime.js` 得画布/堆。并行任务会显著拉大首屏读数，建议在空闲机上重跑一次再定版。
