# 规格 · 开场角色与起始技能选择（v1.7.0 原型线）

```
目标产物   = ui-lab\roles-select.html + ui-lab\角色设定.md
本轮边界   = 不碰主文件（index_arcane_v2.html / dist/*）、不改战斗循环、不加美术资源
零外链     = 不引外部字体/CSS/JS，不塞 base64 图片，file:// 双击即可运行
配色       = 只复用现有令牌（深蓝面板 / 科技青 / 魔法紫 / 金·红强调）
字号       = 仅 24 / 18 / 14 / 12 / 11 五档 + 展示层；中文一律 ≥ 12px（11 档只给拉丁字母与数字）
署名       = 标题页“陈光辉 制作”位置不动
```

## 1. 要解决的三个问题

| 问题 | 本规格的回答 |
|---|---|
| 假选择 | 三角色差异落在**技能组 + 被动 + 起手生命/奥能**三处同时生效，不靠文案装差异 |
| 与天赋双倍膨胀 | 角色只给 **flat 值** 与 **机制修正**；天赋只给 **百分比** 与既有四桶。二者用**不同维度**进公式（见 §3） |
| 工程量 | 只做 3 角色、3 张卡、1 个页面、1 个模型 bot；不新增技能、不改引擎、不动存档格式之外的一行 |

## 2. 三角色设计方案（最终参数表）

沿用项目既有命名，理由：`三角色落地补丁.md` 已按 `characterId` + `warden/ember/gazer` 写过锚点口径，另起一套名字会造成两套 id。数值全部重做。

| | **守拙** `warden` | **疾火** `ember` | **观星** `gazer` |
|---|---|---|---|
| 一句话气质 | 拿身体挡在法术前面的老工事 | 只肯在一次机会里出手的猎手 | 把奥能当水循环用的匠人 |
| 手感 | 重（移速 ×0.90，回蓝 18/s） | 快（移速 ×1.06，回蓝 20/s） | 匀（移速 ×1.02，回蓝 18/s） |
| 起始生命 | **132**（+32） | **96**（−4） | **96**（−4） |
| 起始奥能 | **76**（−24） | **130**（+30） | **112**（+12） |
| 起始技能组 | `flameCone` 焰锥 + `fireball` 火球 | `fireball` 火球 + `blade` 光轮 | `fireball` 火球 + `frost` 冰环 |
| 被动 | `regenBonus +2`、`speedMul ×0.90` | `regenBonus +4`、`speedMul ×1.06` | `regenBonus +2`、`speedMul ×1.02` |
| 成长偏向（奖励权重） | 输出 45 / 生存 55 | 输出 85 / 生存 15 | 输出 55 / 生存 45 |
| 最爽的一刻 | 贴脸同时炸开焰锥 + 火球，一整圈小怪一起碎 | 一发火球接回旋光轮，两只排队的怪一起清掉 | 蓝条见底时下一发已转好，冰环把追兵按住 |
| 弱点 | 奥能 76 撑不到三发大技能；移速最慢，被远程拉扯 | 96 生命，一次贴身接触掉约 7%；无自愈 | 单发爆发最低，清大群靠拖时间；容错来自回蓝，不是血量 |

### 2.1 为什么不做贯穿
主文件 `MAGIC_CONFIG` 里**没有贯穿/穿透投射物**。硬造穿透要改碰撞与命中判定 = 动引擎，违反边界。所以疾火的“精准”落在**高单发 + 高蓝量 + 快移速**，起手用 `fireball` + `blade`（回旋往返，射程够远）。
`bolt` 实测是陷阱：耗蓝 30、DPS 12.7，会抢走主输出蓝量，F1–3 存活率只剩 10–13%，已在 §5 淘汰。

### 2.2 为什么成长只改“奖励权重”
角色若给每层属性成长，就会和天赋的百分比/加点进同一维度。改成只调整**奖励三选一的评分权重**（输出/生存），角色只决定“更容易抽到哪张”，数值仍然全部来自既有奖励与天赋，不存在双倍计入。

## 3. 角色 / 天赋 不重复计（硬规则）

| 维度 | 角色负责（开局种子） | 天赋负责（长期积累） | 合成方式 |
|---|---|---|---|
| 生命上限 | flat `+32 / −4 / −4` | `hpMaxPct` 百分比（乘 `baseHp=100`，+5%/级、上限 2 级） | `round(100*(1+talentHpPct) + mods.hpBonus)` —— 角色 flat **不进**天赋乘区 |
| 奥能上限 | flat `−24 / +30 / +12`，**硬上限 ±30** | `aetherMax`（flat 加项，+15/级、上限 2 级 = +30） | 同向相加，靠预算分离：角色最多 ±30，总贡献硬上限 40（`roleGrowthCap`） |
| 奥能回复 | `regenBonus`（+2 / +4 / +2） | 天赋**没有**该项 | 直接相加 |
| 冷却 | **角色不给**（已移除） | `cdr`（−5%/级，上限 2 级 = −10%） | 冷却只由天赋提供，唯一乘区 |
| 移速 | `speedMul`（×0.90 / ×1.06 / ×1.02） | 天赋只有冲刺冷却，无移速 | 唯一乘区 |
| 伤害% / 减伤% / 结晶经济 | **角色一律不碰** | 天赋四桶封顶（+35% / 30% / +60%） | 角色贡献 0 → 不存在重复计 |
| 起始技能组 | 覆盖 `startCard`（中性角色仍走原选择） | 天赋不产技能 | 角色给最多 2 张，`indexOf` 去重 |
| 成长偏向 | 只改**奖励三选一评分权重** | 天赋是花费结晶的永久加点 | 角色只改“选哪张”，不给数值 |

> `roleGrowthCap = 40`：任何角色到 F20 的成长贡献不超过 40 点，写进落地线常量，防止未来调参无意膨胀。

## 4. `roles-select.html` 界面规格

### 4.1 页面构成（单文件三段）
1. **标题页层** `#titleLayer`：`烬`（展示层）、`EMBERFALL`、`v1.7.0`、tagline、**`陈光辉 制作`（原位置、原级差）**、`开始探索`按钮。
2. **角色层** `#roleLayer`：覆盖在标题页之上（标题页降亮 55% 保留在背后可见），面板 1020px 宽，深蓝 `--panel` + 1px 金边 `rgba(255,194,71,.26)`。
3. **bot 面板**：面板底部的 `<details>`，折叠时不占视觉权重。

### 4.2 每张卡（列宽 1fr，三列并排，≥1100px）
自上而下：符印 SVG（56px）→ 角色名 18px → 一句话差异 12px → 生命/奥能双条（`--tech` / `--magic`，条内标数值）→ 技能组两枚（几何图标 + 12px 名）→ 被动 12px → 成长 12px → 右下角序号 `1 / 2 / 3`（11px 数字）。

### 4.3 符印（纯几何，零位图）
- 守拙：六边形外框 + 内环 + 4 段短弧（护壳），色 `--tech`。
- 疾火：两道对置尖弧构成矛尖 + 中心点 + 4 条放射短线，色 `--gold`（描边 `--bad` 1px）。
- 观星：双环反向 + 3 个节点 + 连接弧（循环），色 `--magic`。
全部用 `<svg>` 的 `circle / path / polygon / line` + `linearGradient / radialGradient` + CSS `filter: drop-shadow` 做发光。

### 4.4 交互（3 秒内可完成）
- 悬停：`translateY(-3px)` + 边框转金 + 符印 `drop-shadow` 加强，120ms `cubic-bezier(.2,.9,.25,1)`。
- 选中：金色 2px 顶条 + 边框 `--gold` + 右上角对钧符印 + `aria-checked="true"`；同组只能一张。
- 键盘：`1/2/3` 切换高亮，`Enter` 确认，`↑/↓/←/→` 也接受；`Tab` 正常聚焦。
- 确认后：卡片区不动，底部条变为「已选择 · 观星（按 Enter 开始）」，不跳页（原型不真开局）。
- `prefers-reduced-motion: reduce` 时关闭位移与发光过渡，只留边框变化。

### 4.5 字号与中文下限
| 档 | 用途 |
|---|---|
| 展示层 | `clamp(40px,9vw,72px)`：标题页 `烬` |
| 24 | 面板标题「选择角色」 |
| 18 | 角色名 |
| 14 | 数值主行、按钮 |
| 12 | 一句话差异 / 被动 / 成长 / 提示（中文最小档） |
| 11 | 仅拉丁与数字：`HP` `AE` `1/2/3` `样本 300` |

### 4.6 响应式
`≤1100px` 三列 → 纵向单列（卡变横排：符印左、信息右），`≤620px` 数值条拆两行；标题页在窄屏下不缩放字号。

## 5. bot 实测（引擎模拟器，10 层以上）

**口径**：复用 `tools/sim_panel/sim.js`（`runOne(seed, bot, 'normal', {charSpec})`），普通难度、0 天赋、20 层上限，每角色 **400 样本**，同种子可复现（连跑两次结果完全一致）。探针脚本 `tools/role_probe.js`，模拟器本体未改一行。

**结果**

| 角色 | 样本 | F1–3 存活率 | F1–3 平均耗时 | 平均死亡层 |
|---|---|---|---|---|
| 守拙 | 400 | 66.8%（267/400） | 379.8s（n=267） | 5.72（251 例死亡） |
| 疾火 | 400 | 68.8%（275/400） | 275.0s（n=275） | 4.88（328 例死亡） |
| 观星 | 400 | 69.8%（279/400） | 295.7s（n=279） | 4.47（251 例死亡） |
| 无角色（基线） | 400 | 64.5%（258/400） | 308.8s（n=258） | 4.63（280 例死亡） |

极差 3.0 个百分点（门槛 8pp 内），三值互不相等。

**指标定义**
- `F1–3 存活率`：通过第 3 层首领的样本 / 400。
- `F1–3 平均耗时`：**仅统计通过者**的 F1→F3 累加秒数（分母写清 `n=通过数`）。
- `平均死亡楼层`：死亡样本的死亡层均值，另报死亡样本数。

**调参淘汰记录**：`bolt` 起手（存活 10–13%）、`heal` 起手（100%）、观星回蓝 +6（77.5%，差 10.7pp）、守拙 `frostRing` 起手（31.5%、552s）全部被实测淘汰。

## 7. 验收门

1. `roles-select.html` 断网双击可开；`Grep` 确认无 `http` / `base64` / `@import`。
2. 三卡 1/2/3 键切换、Enter 确认、悬停位移均可用；`aria-selected` 同步。
3. 中文最小字号实测 ≥ 12px（浏览器计算样式抽查 3 处）。
4. 标题页 `陈光辉 制作` 存在且未改字号/位置。
5. bot 面板可一键重跑；同 seed 两次结果完全一致；输出含样本数。
6. 三角色 F1–3 存活率差距 ≤ 12pp 且三者**不相等**；平均死亡楼层三者不同。不满足则调角色参数重跑（不调模型）。
7. 主文件字节数与 MD5 复算不变。

## 8. 风险

| 风险 | 处置 |
|---|---|
| 模型 bot 与实机偏差 | 页面与报告首行标注“模型 bot”，列 3 个标定常数；P0 优先复用实机模拟器 |
| 已有 `startCard` 选择与角色技能组冲突 | 角色覆盖 `startCard`；中性角色保持原逻辑；落地时在 `applyCharacterCards` 去重 |
| 观星回蓝 +6 强势 | 若 bot 显示观星前 3 层显著领先，先降 `regenBonus` 到 +4 再复核 |
