# U7 · 模板房间 + 柱体碰撞（A4 / A5 / A6 合并）

> 出处：`.spec/round4-5-merge.md` 的 **A4**（房间形状多样化）、**A5**（手工模板房间）、**A6**（柱状掩体参与碰撞）。
> 三者在同一句根因里：房间是"盖章"——每间都是同一个圆角矩形，柱子只是 4 根 6×24px 的贴墙装饰条。

---

## 1. 根因

1. **形状**：`generateFloor()` 里 `addWalkRect(room.x, room.y, room.w, room.h)` —— 每间房的可行走区就是它的外接矩形，`bakeScene()` 里所有地面 / 墙 / 光 / 装饰画笔也都以 `roundRectPath(room)` 为唯一几何。玩家在地图上看到的 7 个房间是同一个模子印出来的，走位没有地形差异。
2. **模板**：房型（battle / elite / chest…）只影响"刷什么"，不影响"这间房长什么样"；机械层虽然有 `assignMechRoomVariants()`，但只换装饰配色，不换空间。
3. **掩体**：`paintPillars()` 只是四角 6×24px 的护墙条，`isWalkableCircle()` 完全不认识它们——柱子是纯贴图，不参与任何碰撞，也就没有任何战术价值（不能卡位、不能绕后、不能挡视线）。

## 2. 设计：三层几何模型

保留"碰撞 = 可行走区域并集"这套低风险系统，只把"并集"从"纯矩形"扩成三类原语：

| 原语 | 字段 | 作用 | 语义 |
|---|---|---|---|
| 矩形 | `state.walkRects` | 地板 / 走廊 | 采样点在任一矩形内 = 可走（沿用旧逻辑） |
| 圆盘 | `state.walkCircles` | 圆形首领场 | 采样点在圆内 = 可走（新增，取并集） |
| 实心障碍 | `state.walkBlockers` | 切角块 / L 形缺口 / 立柱 | 圆形角色与该障碍重叠 = **不可走**（新增，做减法） |

`isWalkableCircle()` 的判定顺序：**并集采样 → 再做减法**。这样：
- 切角八边形 = 整矩形 **−** 4 个角块；
- L 形 = 2 个矩形并集（缺口天然不在并集里，不占 blocker）；
- 圆形首领场 = 内切圆盘（不铺矩形，所以四角天然走不进去）；
- 立柱 = 任意形状上 **−** 1~2 个圆柱。

### 2.1 模板表（3 主题 × 2 模板 + 首领场）

| 主题 | 模板 A | 模板 B | 首领房（每层） |
|---|---|---|---|
| mech 装配层 | `foundry`：八边切角 + 2 根立柱（左右分列） | `duct`：L 形（右上切走 42%×46%）+ 1 根立柱压在内转角 | `arena`：圆形 |
| rune 符文层 | `ring`：八边切角 + 0 柱（中央符文圈为主视觉） | `cross`：矩形 + 2 根立柱上下分列 | `arena`：圆形 |
| void 虚空层 | `span`：八边切角 + 2 根立柱对角 | `ledge`：L 形 + 1 根立柱 | `arena`：圆形 |

- 分配规则：`hash01(floor, room.id)` 决定 A/B（同层重烘焙结果一致）；**出生房 / 休整房强制 `rect`**（保证起手和回血点开阔、不被柱子卡住）；**首领房强制 `arena`**（圆形对枪手感 + 视觉上"这就是决斗场"）。
- 切角比例 `cornerCut = 0.24 × min(w, h)`；首领圆半径 `= min(w, h) / 2`。
- 立柱半径 `24px`（玩家 14px），位置按房间短边比例摆放，保证不压中央符文圈、不挡门洞。

### 2.2 视觉语言（必须让玩家"看得出哪里能走"）

几何改了但贴图不动 = 玩家会撞空气墙。所以 `bakeScene()` 在 `paintRoomVignette()` 之后插入 `paintRoomShapeMask()`：
- 把"不可走"的那块（切角三角形 / L 形缺口 / 圆外四角）**压成更深的结构材质**（近黑 + 主题色微染 + 内缘 1px 亮边 + 铆钉），读起来是"抬高的设备基座 / 断开的平台边缘"；
- 沿新边界画一条主题色描边，和地面之间有 1px 亮线，明确"这里是边"；
- 立柱在烘焙期只画**投影 + 底座环**，柱身在运行时 `drawRoomPillars()` 里画（在 `drawScene()` 之后、实体之前），这样柱子不会被地板光盖住、又不会遮住玩家与子弹。

## 3. 保留的既有约束

- 不越房：`roomAt()` / `isInsideRoom()` 仍是矩形口径，房间归属、迷雾、锁门判定完全不变。
- 进房锁门 / 清房开门：`collectDoors()` 只扫房间外墙边与走廊的重叠，形状变化不影响门洞位置（切角不切到墙中点，L 形缺口让开墙中点）。
- 走廊巡逻不追人：走廊矩形不在 `walkBlockers` 里，`findCorridorSpot()` 逻辑不变。
- 难度三档只在生成时生效：形状不改刷怪数量公式；只把"出生点落在柱子/缺口里"的极端情况用 `nudgeOutOfBlockers()` 推开。
- Boss 两阶段机制不变：圆形只改可行走区，`updateBoss` / 重招轮转 / U4b 招牌全都不碰。

## 4. 断言（`tools/arcane_u7.js`，端口 9495，共 13 项）

1. 结构就位：`ROOM_TEMPLATE_CONFIG` / `walkBlockers` / `walkCircles` / `isWalkBlocked` / `paintRoomShapeMask` / `drawRoomPillars` 存在。
2. 模板覆盖：3 主题各有 A/B 两个模板；同层至少 2 种不同 `shape`。
3. 首领房 `shape === 'circle'`，`walkCircles` 有且只有 1 个圆盘；房心可走、**至少 3 个外接矩形角点**在圆外（个别楼层走廊贴角时会有一个角落落在走廊矩形里，属合法覆盖，断言取 ≥3 并在证据里打印逐角 describe）。
4. 形状生效：切角房"角点不可走 / 房心可走"；L 形房"缺口不可走 / 两块主体都可走"。
5. 圆形场：圆心可走、外接矩形四角不可走（差值 ≥ 100px 的判定）。
6. 立柱碰撞：柱心 `isWalkableCircle` 为 false；柱外 `r + radius + 2` 处为 true；同层柱子数量 ≥ 2。
7. 真实移动：把玩家放在柱子一侧、朝柱子方向持续输入 0.5s，**玩家不会穿过柱心**（位移 < 柱半径）。
8. A/B：`setRoomTemplates(false)` 后切角点变可走、立柱归零、`walkBlockers` 清空；再开回来恢复。
9. 刷怪安全：所有敌人初始位置 `isWalkableCircle` 为 true（含形状房与柱子）。
10. 截图：同一机位 4 张（八边形房 / L 形房 / 圆形首领场 / 关闭后矩形对照），像素证据（`Page.captureScreenshot`）。
11. fps ≥ 60（跳过前 40 帧预热）、`__errors` 为空。
12. 14 套回归全绿。

## 5. 取舍 / 风险

- **不做真正的"任意多边形"**：只做 3 种形状 + 柱体。再多就需要重写所有地面画笔（`paintRoomFloor` / `paintThemeFloorDetail` / `paintMechRoomLayer` 都以矩形为画布），回归面会扩到全部 14 套。
- **柱体只挡移动、不挡子弹**：挡子弹要改 `projectiles` 与 `enemyBullets` 两条更新线，且"打不中"的挫败感强于战术收益。作为已知限制记录；如果后续 A8 爆炸桶需要掩体语义，可在 U10 一起补。
- **小地图仍是矩形**：`drawMinimap()` 画的是房间外接矩形，形状不反映。视觉信息在主画面已经足够，先不动（动了要同步迷雾 / 探路动画）。
- **风险点**：L 形 / 圆形房的中央符文圈与四角节点装饰需要跳过（否则装饰画在缺口里），`assignRoomTemplates()` 之后 `state.decor` 生成处要按形状过滤。
