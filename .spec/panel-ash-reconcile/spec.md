## 1. 批次一：面板对账剩余 4 条

### #1 焚稿面板卡列表的「伤害」改为按当前层数现场算

**现状（已核实）**
- 位置：`index_arcane_v2.html` L42896–42926 `ashRenderList()`。
- 写法：`'<div class="ash-card-meta">伤害 ' + Math.round(card.damage || 0) + ...`
- 问题：只读 `card.damage`（火球恒 24），不乘灰烬增伤，也不乘任何实战乘区；面板写的是基础值，玩家看到的是假数。

**一致口径的参照**
- 「灼身代价」行在 `ashSyncUI()` L42997–43012：只从 `ASH_CONFIG` 读，`stacks` 现算，`toFixed(2)`，缓存文本比对后再写 DOM。
- 实战伤害链路唯一出口：`getMagicDamage(magic, fusion)` L43021–43047（含 `state.mods.damageMul`、科技、融合、标签、超频、副槽、遗物、开篇赠礼、`ashDamageMul()`）。

**改法（决定）**
1. 新增一个函数（放在 `ashRenderList()` 之前）：

```js
/**
 * 计算焚稿面板里某张卡此刻的实战伤害（与施法链路同源）
 * ------------------------------------------------------------
 * 为什么不用 card.damage：面板要反映"现在烧掉会损失多少输出"，
 * 而实战伤害会吃全局增伤、科技、融合与灰烬层数，写死基础值就是假数。
 * @param {Object} card 魔法配置（MAGIC_BY_ID 中的一项）
 * @returns {number} 当前实战单发伤害；0 伤害卡返回 0
 */
function ashCardDamageNow(card) {
  if (!card) return 0;
  const fusion = (typeof getFusionForMagic === 'function') ? getFusionForMagic(card.id) : null;
  return getMagicDamage(card, fusion);
}
```

2. 新增一个纯格式化函数（不改数值，只决定 24 还是 26.9）：

```js
/**
 * 把伤害数值格式化成面板文案：整数不带小数，非整数保留 1 位
 * @param {number} value 伤害数值
 * @returns {string} 展示用字符串
 */
function ashFormatDamage(value) {
  const n = Number(value) || 0;
  return Math.abs(n - Math.round(n)) < 0.05 ? String(Math.round(n)) : n.toFixed(1);
}
```

3. `ashRenderList()` 内把 `Math.round(card.damage || 0)` 换成
   `ashFormatDamage(ashCardDamageNow(card))`。
4. `.ash-card-meta` 的 CSS 与结构不动；`data-*` 不新增。

**预期读数（口径：整局起始，无任何遗物 / 科技 / 祭坛）**
| 灰烬层数 | 火球面板伤害 | 算式 |
|---|---|---|
| 0 | 24 | 24 × 1.00 |
| 2 | 26.9 | 24 × 1.12 |
| 4 | 29.8 | 24 × 1.24 |

> 说明：任务描述里的「4 层 31.5」只有在额外全局增伤存在时才成立
> （24 × 1.24 × 1.0585 ≈ 31.5）。改后走 `getMagicDamage`，这类额外乘区会被一并算入，
> 所以两种观测都能对上；报告里必须写清当局面板乘区。

**风险与边界**
- `getMagicDamage` 依赖 `state.mods` / `state.ownedTech`；焚稿面板只在 `state.status==='playing'` 时可开，成立。
- `getFusionForMagic` 不存在时回退 `null`（防御旧包），不抛错。
- 面板打开期间世界冻结，层数与乘区不变；烧卡后 `ashRenderList()` 重建，数值自然刷新。

### #5 图鉴「卡牌」行的数值口径

**现状（已核实）**
- 位置：`index_arcane_v2.html` L54052–54061 `codexSourceEntries('cards')`。
- 写法：
  `'奥能 ' + card.cost + ' · 冷却 ' + card.cooldown + 's · 伤害 ' + (card.damage != null ? card.damage : '—')`
- 问题：`damage = 0` 的治疗符 / 护身符阵也会打印「伤害 0」，把「没有伤害」说成「伤害为零」；
  图鉴是永久档案，应展示**卡面基础口径**，不掺当局乘区（这点与 #1 相反，必须区分）。

**改法（决定，按用户裁定）**
只改这一分支的 `stats` 组装，抽出「伤害段」：
1. `damage > 0` → `伤害 N`（仍是基础面板值，不乘局内乘区）。
2. `damage` 为 0 / 缺失 → **整段不显示**（不用「伤害 0」，也不用「回复 N」）。
   理由（用户原话）：写 0 会被读成「这张卡打不出伤害」的缺陷，而不是「这张卡不是伤害卡」。
3. 奥能 / 冷却段保持原样；科技卡分支（无 `cost`）不动。

建议实现为一个小函数并加函数级注释：

```js
/**
 * 图鉴「卡牌」页签的伤害段（永久档案口径：只用卡面基础值）
 * 非伤害卡返回空串，由调用方 filter 掉整段，避免出现「伤害 0」
 * @param {Object} card MAGIC_CONFIG 中的一项
 * @returns {string} 例如「伤害 24」；非伤害卡返回 ''
 */
function codexCardDamageText(card) {
  const dmg = Number(card && card.damage) || 0;
  return dmg > 0 ? '伤害 ' + dmg : '';
}
```

然后 `stats` 用 `[ '奥能 …', '冷却 …s', codexCardDamageText(card) ].filter(Boolean).join(' · ')`。

**验收**
- 治疗符行不再出现「伤害 0」，只保留「奥能 28 · 冷却 3.2s」。
- 护身符阵行不出现「伤害 0」。
- 火球行仍是「奥能 15 · 冷却 0.55s · 伤害 24」。
- 科技卡行仍是「科技 · 被动」一类，不受影响。
