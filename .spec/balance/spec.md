# 规格：第 6–10 层战斗强度量化诊断（不改主文件数值）

> 性质：**诊断**。本轮只新增 `tools/arcane_balance.js` 与 `BALANCE_REPORT.md`，
> 不改 `index_arcane_v2.html` 的任何玩法数值；只有发现"明显 bug"才单独报告。
> 用户既有裁定：规格自审通过即进入实现（不需要等确认）；最终改哪些字段等用户拍板。

## 1. 目标曲线（对账基准，写进报告）

| 项目 | 目标 |
| --- | --- |
| 战斗房清场时间 · 第 6 层 | 18–25s |
| 每层增长 | +8%–12% |
| 战斗房清场时间 · 第 10 层 | 30–40s |
| Boss 战 · 第 6 层 | 45–60s |
| Boss 战 · 第 10 层 | ≤ 90s |
| 单场最大生命损失 | ≤ 40%（标准难度 / 正常走位 / 无治疗） |
| 每层被迫重开/死亡期望 | 第 6 层 ≤ 8%，第 10 层 ≤ 35% |
| 同场敌人数 | ≤ 6 |
| 同屏投射物（敌弹 + 玩家弹） | ≤ 30 |

第 7–9 层目标按 22.5s 中值 ×1.08/1.12 递推：
7 层 19.4–28.0s、8 层 21.0–31.4s、9 层 22.7–35.2s；第 10 层以用户给定 30–40s 为准。
第 5 层作为"断崖参照"实测，不设目标。

## 2. 固定实验条件

- 无头 Edge + CDP（沿用 `tools/arcane_profile.js` 的 `prepareProfile/killEdge`，端口 9544）。
- 标准难度（`state.difficulty='normal'`）；关闭自适应降档（`enemies.setAdaptive(false)`），
  否则 headless 掉帧会把 5–6 只降到 3–4 只，破坏可比性。
- 玩家构筑固定：`['fireball','flameCone']`（一条投射 + 一条 AOE），**禁治疗**；
  清空 `ownedTech/ownedMagic 其它项、fusions、relics`；`state.mods.damageMul/cooldownMul=1`；
  血量/奥能满值开场；每场前 `setHp(hpMax)`。
- 目标选择：当前房间内优先**血量最低**的敌人（同血量取最近）。
- 走位 bot：与最近敌人保持 **180–260px**；靠太近后退、太远靠近、横向绕圈；
  每步用 `walkableAt` 预判落点，避免贴墙；不使用治疗；真实模式不做"额外开挂"。
- 瞄准：`setAimExact(angle)` 钉死角度（跳过平滑滞后），火球打提前量。
- 取样：第 **5、6、7、8、9、10** 层各 **12 次**（≥8）；Boss 第 6/10 层各 6 次。
- 时间口径：用游戏内 `state.elapsed`（模拟秒），避免 headless 定时抖动；
  通过临时接管 `requestAnimationFrame` + 定步长 `update(1/60)` 加速模拟（固定 dt 更可比）。
  fps 单独在"正常 RAF 渲染"窗口内测 3s，不被加速影响。

## 3. 两种模式（分开列表）

- **真实模式**：承伤正常，记录损血比例、死亡、清场时间、投射物峰值、敌人数/总血/混编。
- **无敌模式**：每步把 HP 拉满，并可选"奥能不限"（仅用于 DPS/清场时间上限校准）；
  与真实模式结果分表，不混用。
- 每层先跑 12 次真实模式；无敌模式每层 4 次，仅在第 10 层超时明显时用于区分
  "敌人太肉" 还是 "奥能不够"。

## 4. 单场采样字段

`floor / room(w,h,areaMul) / 敌人数 / 血量总和(含盾) / 混编种类 / DPS /
清场时间 / 最大损血% / 投射物峰值 / fps / 是否超时 / 是否死亡`。

- 清场 = 本房 `state.enemies` 中 `roomId` 匹配的敌人归零。
- DPS = 本场有效伤害总和 / 清场时间（超时则用已造成伤害 / 运行时长，并标 timeout）。
- 超时上限：普通房 75s、Boss 90s（模拟秒）；超时仍记录数据。
- 敌人数上限检查：取每房 `room.enemyCount` 与实战 `live` 峰值。
- 投射物峰值 = `state.bullets.length + state.projectiles.length`。

## 5. 对账与判定

- 偏差 = (实测中位数 − 目标中值) / 目标中值；同时看是否落在目标区间。
- 判定：落在区间 = 合理；低于区间下沿 >15% = 偏松；高于区间上沿 >15% 或超时 = 偏硬。
- 输出总表：`层数 | 目标 | 实测(中位/区间) | 偏差 | 判定`，Boss 单列。
- 必答三问：
  1. 第 6 层相对第 5 层是否断崖（用清场时间、敌人数、总血量三项的环比）；
  2. 曲线形态（线性/指数/后段陡增）：看逐层增长率 g_n 是否稳定/递增；
  3. 偏差最大层（按 |偏差| 排序，超时按 100% 计）。
- 样本量说明：死亡率为点估计；0/12 的 95% 上界约 25%，报告里注明"样本不足以严格证明 ≤8%"。

## 6. 调参建议（只给方案，不落地）

候选字段（按实测结果选 3–5 个，报告给"字段 → 现值 → 建议值 → 预期效果"）：

| 字段 | 现值 | 建议方向 |
| --- | --- | --- |
| `GAME_CONFIG.floorScale` | 1.12 | 降到 1.06–1.08（压后段血量指数） |
| `DIFFICULTY_CONFIG.pressure.hpStep` | 0.06 | 降到 0.03–0.04 |
| `DIFFICULTY_CONFIG.pressure.maxMul` | 1.55 | 降到 1.35 |
| `ENEMY_BUDGET_CONFIG.battle/elite` | [5,6]/[4,5] | 后段降为 [4,5]/[3,4] |
| `BOSS_CONFIG.hpFloorMul / hpCap` | 1.35 / 4200 | 1.18–1.22 / 3400–3600 |
| 玩家伤害成长（`state.mods.damageMul` 来源） | 无每层成长 | 每层 +5%~8%（或等价奖励权重） |

预测验证：用同一脚本，在**内存里覆盖**上述字段（不写主文件），
对第 6–10 层各跑 4 次（Boss 各 3 次），输出"改后"预测对账表；
预期目标：6 层落在 18–25s、10 层落在 30–40s、Boss 10 层 ≤90s、损血 ≤40%。

## 7. 产出

- `tools/arcane_balance.js`：CDP + bot + 采样 + 对账 + 预测 + 断言；
  退出码非 0 表示结构性断言失败（目标对账只报告，不判红）。
- `BALANCE_REPORT.md`：目标曲线、实测表、偏差判定、三问结论、最不合理层、
  调参建议表（字段/现值/建议值/预期）、预测对账表、风险与样本局限。
- `.screenshots/balance/`：第 6 层与第 10 层战斗现场 2–3 张（>60KB），
  附 `balance-result.json`。
- 收尾：清理 profile/日志，报 C 盘剩余空间；PROGRESS 追加本轮条目。

## 8. 断言清单（脚本自检）

1. 第 5–10 层每层真实样本 ≥ 8 次；
2. 每场同房敌人数 ≤ 6（首次刷怪与实战峰值）；
3. 同屏投射物峰值 ≤ 30；
4. 所有采样都有 `clearTime/dps/hpLoss/projectilePeak/enemyCount` 字段；
5. 第 6/10 层 Boss 各 ≥ 3 次采样；
6. 预测轮有覆盖记录（`applied` 字段可回读）；
7. 无运行时报错（`__roamDebug.errors()` 与 Runtime.exceptionThrown）；
8. fps ≥ 60（PERF，只记录不判红）；
9. 截图 ≥2 张且 >60KB。

## 9. 风险

- bot 走位水平有限，真实模式损血可能偏高 → 同时给无敌模式 DPS 上限对照。
- 随机房间大小/混编会带来方差 → 12 次取样取中位数，并记录区间。
- 加速模拟只在"无渲染"下进行，fps 另行实测；两者口径分开标注。
- 结论仅覆盖"固定两技能、无科技/遗物"的标准基线；真实通关构筑更强，报告中注明。
