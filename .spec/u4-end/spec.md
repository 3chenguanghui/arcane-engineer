# U4 · 终点 / 通关：让一局存在「完成」而不是只有「死亡」

> 出处：`.spec/round4-5-merge.md` 结构性根因 **L4**（判定成立）。
> 现状：`loseGame()` 是唯一收束路径；`descendFloor()` 永远 `floor += 1`，楼梯无限。
> 玩家永远不知道"这套构筑够不够用"，因为游戏没有"够"的定义。

---

## 1. 根因（一句话）

**只有失败结算、没有完成结算**：一局游戏的结局只有"死"，没有"过"，
所以成长曲线没有验收点，Build 的强弱也没有终点裁判。

## 2. 改法

1. `GAME_CONFIG.finalFloor = 3`：一季 = 机械 / 符文 / 虚空各一层（正好覆盖 3 个区域池与 3 个首领）。
2. `isFinalFloorRun()`：`floor ≥ finalFloor && !endless && !runCompleted`。
3. `onBossDefeated()` 的最末层分支：
   - 不再追加"首领额外三选一"（避免通关前一秒还在选卡）；
   - 设 `state.victoryTimer = 2.4s`，让击杀演出与掉落先播完。
4. `winGame()`：`status='won'`、`mode='result'`、`meta.clears += 1`、存档；金色涟漪 + 上升爆点 + 轻震屏 + `reward` 音效。
5. `showVictory()`：金色通关面板（与死亡面板同结构），统计：到达楼层 / 击杀 / 清空层数 / 存活时间 / 构筑规模 / 最高连击 / 遗物种类 / 本局结晶 / 累计结晶 / 通关次数 / 最佳楼层。
6. `continueEndless()`：`endless=true` 返回游戏，楼梯继续按原规则下行（楼层继续增长，不再弹通关）。
7. 键盘：`R` 重开沿用原逻辑；`E` 楼梯逻辑完全不动。

## 3. 保留约束

- 不改 Boss 两阶段、不改楼梯解锁条件（`bossUnlocked`）、不改清房判定。
- 不改难度三档（通关面板只显示当前难度名）。
- 不改永久存档结构，只新增 `meta.clears`（缺失时按 0 处理，旧存档兼容）。
- 单文件零依赖、无图片，面板全部 HTML + CSS。

## 4. 验收断言（`tools/arcane_l4.js`，端口 9491）

| # | 断言 | 口径 |
|---|---|---|
| 1 | 配置 | `finalFloor === 3`、`victoryDelay ≈ 2.4` |
| 2 | 非末层不触发 | 第 1 层击败首领 → 2.8s 后 `runCompleted=false`、无通关面板 |
| 3 | 末层触发 | 第 3 层击败首领 → 2.8s 内 `status='won'`、面板含 `victory-modal` |
| 4 | 战绩 | `meta.clears` +1、`bestFloor ≥ 3`、面板出现"通关次数" |

| 7 | 无尽不再弹 | 无尽下到第 6 层再击败首领 → 不弹通关面板 |
| 8 | 死亡仍走旧面板 | `loseGame` 路径保留（静态断言 UI 文案未变） |
| 9 | 截图 | 通关面板截图 > 10KB |
| 10 | 回归 | 14 套全绿 + fps ≥ 60 |

## 5. 设计取舍

- **D1 3 层为一季**：与 3 池 / 3 首领的自然周期一致；想更长可改 `finalFloor` 一个数。
- **D2 末层不做额外三选一**：通关面板负责"收束"，避免最后一秒还在做构筑决策。
- **D3 无尽是显式选择**：不剥夺喜欢无限下潜的玩家，也不会让"通关"变成强制结局。
- **D4 通关面板保留永久天赋升级**：与死亡面板行为一致，避免玩家在通关后必须重开才能花结晶。
