# P0-1 元素附着与反应 · 规格（先行，落码前）

> 本轮目标：把"融合"从选卡阶段延伸到战斗中的即时判断。
> 单文件零依赖、函数级中文注释、总开关关闭时与现状逐字节同行为。

## 1. 总开关

```js
const ELEMENT_CONFIG = {
  enabled: true,   // 唯一总开关
  ...
};
```

- `enabled=false` 时：
  - `damageEnemy` 里附着入口第一时间 `return`，不分配对象、不写字段、不查表；
  - `updateEnemies` 不推进附着计时，`updateElementClouds` 直接空转；
  - `drawElementStatusIcons` / `drawElementClouds` 第一行 return；
  - 敌人对象上**不会出现 `elem` / `elemCd` 任何新字段**，`state.elementClouds` 保持 `undefined`。
- 因此关闭后：伤害数值、击退、顿帧、飘字、演出分级、随机数消耗全部与现在一致。
- 测试口径：同一发 `damageEnemy(..., { noCrit:true, abilityId:'fireball' })`，开/关两次的 `damage` 与 hp 差必须完全相等，且关闭时 `enemy.elem` 不存在。

## 2. 附着状态机

### 2.1 五种附着（不是五种元素，而是五种"状态"）

| key | 名称 | 来源（技能 → 附着） | 持续 | 表现 |
|---|---|---|---|---|
| `fire` | 灼烧 | 火球 / 熔岩地裂 / 喷火锥 / 符文雷 / 霜焰爆发 | 4.0s | △ 三角徽记 |
| `ice` | 冰冻 | 冰环 / 冰霜环 / 寒霜领域 / 引力井 | 3.0s | ◎ 六角徽记 |
| `thunder` | 感电 | 雷击 / 奥术雷池 / 雷暴无人机 / 连锁扩散 | 2.2s | ⌁ 折线徽记 |
| `wet` | 湿身 | **冰附着到期融化** / **霜爆后的融水** | 3.0s | ≋ 波浪徽记 |
| `poison` | 淬毒 | 回旋刃 / 符文轨道 | 4.0s | ☣ 菱形徽记 + 小点 |

- 来源表集中在 `ELEMENT_CONFIG.sources`，**以 abilityId 为准，不按旧 tag 猜**：
  旧 tag（投射/范围/连锁/回旋/布防）仍只负责标签乘算，不参与附着判定。
- 为什么 `mine` 给火、`blade` 给毒：符文雷是爆炸符文（有火），回旋刃是淬毒刃（有持续伤口语义）。
  两者都不改卡面 tag、不改伤害、不改冷却，只在命中入口追加一个状态。

### 2.2 怎么加

- 只在 `damageEnemy` 的**直接命中**路径加（`opts.abilityId` 存在且本次非致死）。
- 爆炸/范围波及也会带 `abilityId`（`applyExplosion` 透传），所以 6 条 AOE 与 5 种基础形状全部能附着。
- 反应伤害自身调用 `damageEnemy` 时带 `opts.reaction=true` + `noElement=true`，**不会再挂附着、不会套娃**。

### 2.3 持续多久 / 能否叠加

- **不叠层**：重复命中同一 key 只刷新剩余时间（取较大值），不累计层数、不叠伤害。
- 理由：本作没有"层数" UI，叠层会让图标数字与伤害口径一起变复杂，违背"不增加操作复杂度"。

### 2.4 多附着共存

- 各 key 独立计时，互不覆盖。
- 同时最多 **3 种**（超出时丢弃最早挂上的那一种），保证头顶图标永远 ≤3 个、不糊。
- 例：冰 + 火 + 毒 可以同时存在；此时火命中会先判"火+冰"（霜爆），冰被消耗，火与毒仍在。

## 3. 三种反应

判定顺序固定（同一次命中最多触发 1 种反应）：

1. 火命中带 `ice` → **霜爆**
2. 雷命中带 `wet` → **传导**
3. 火命中带 `poison` → **燃云**

### 3.1 霜爆

- 伤害口径：`round(触发本次命中的面板伤害 × 0.55)`，最少 1。
- 范围：以被命中敌人为圆心、半径 92px，最多结算 3 只（含本体）。
- 消耗：消耗 `ice`；随后给本体挂 `wet` 2s（"冰被炸碎、身上是水"），形成"霜爆 → 雷传导"的连招。
- 演出：S1（双环 + 12 片冰晶碎屑 + 轻震 2.0 + 顿帧 40ms + 飘字「霜爆」）；不走 S2。
- 频率上限：同一目标 0.6s 内只结算一次；冷却中再次命中只刷新附着，不重复爆。

### 3.2 传导

- 伤害口径：`round(触发本次命中的面板伤害 × 0.45)`，最少 1。
- 范围：以被命中敌人为圆心、半径 150px，最多再串 3 只（不含本体额外一次）。
- 消耗：消耗 `wet`。
- 演出：S1（3 条折线电弧 + 6 颗电火花 + 顿帧 30ms + 飘字「传导」）；不走 S2。
- 频率上限：同目标 0.6s。

### 3.3 燃云

- 伤害口径：首帧不结算，生成一片云；云每 0.5s 结算一次，共 6 跳（3s），每跳 `round(触发面板 × 0.25)`。
- 范围：半径 100px 的地面云，所有云内敌人每跳各吃一次；单云最多 4 只/跳。
- 消耗：消耗 `poison`。
- 演出：首帧 S1（绿焰环 + 飘字「燃云」），后续每跳 S0（只跳小号伤害数字，不震屏不叠粒子）。
- 频率上限：同目标 0.6s；场上最多 4 朵云（超出替换最旧的一朵，防刷屏）。

### 3.4 反应伤害是否吃标签 / 暴击

**结论：不吃暴击、不吃裂印 / 核心暴露 / 先手这些"命中瞬间"倍率；也不二次乘标签。**

- 反应基数取"触发这一发的面板伤害"（`getMagicDamage` 的结果），标签乘算在那一层已经算过一次，反应不再乘第二遍。
- `damageEnemy` 内对 `opts.reaction` 跳过暴击、裂印、核心暴露、先手，保证反应伤害是稳定的、可预期的。
- 理由：反应是"规则奖励"，不是"又一次平A"；若吃暴击，会在高暴击 build 下指数放大，且同一套元素组合的伤害方差过大，难以平衡。

### 3.5 触发频率上限汇总

| 层级 | 上限 | 目的 |
|---|---|---|
| 单目标单反应 | 0.6s | 同帧多次命中 / 多弹体叠打不重复结算 |
| 单目标反应种类 | 每种独立冷却 | 霜爆后立刻燃云仍可触发 |
| 燃云 | 场上 4 朵 | 防止连发把地面铺满 |
| 演出 | 反应固定 S1（燃云后续 S0） | 不占用 S2 预算，不打断 boss 演出 |

## 4. 与现有系统的关系

- **标签系统**：完全不动。`tagDamageMul` 仍只影响首次命中伤害，反应只继承结果。
- **融合系统**：不动配方与数量；融合技通过 `abilityId` 自动继承元素（如 `chainSpread` 仍算雷、`frostFlame` 的延迟爆算火）。
- **S0/S1/S2 分级**：反应走 `fxTierEvent('elementReact')`，该 kind 不在 S2 白名单，永远是 S1；燃云后续跳伤走 S0 飘字。反应击杀仍走正常 `killEnemy`，击杀演出按原有分级。
- **处决 / 破防（P0-2）**：后续在 `damageEnemy` 同层接入，互不依赖；反应伤害可以推进"破防窗口"的血量条件，但不直接触发处决。

## 5. 视觉与文字反馈（不只靠颜色）

- 敌人头顶 **形状化徽记行**（血条上方）：
  - 每种附着有独立字形 + 独立外框：圆 / 六角 / 三角 / 方 / 菱形；
  - 徽记右下角带剩余秒数（整数），不用颜色也能读出"还有什么、还剩多久"。
- 触发反应时：敌人身上再叠一圈对应形状的环（霜爆六角、传导折线、燃云波浪），并飘出反应名大字。
- 音效复用现有 `frost / bolt / fire`，不新增音频资源（保持零外部请求）。

## 6. 必须覆盖的验收

1. 命中不存在的目标：不崩溃、不计数。
2. 目标死亡时：`killEnemy` 清空 `elem/elemCd`，且致死那一发不触发反应。
3. 同帧多次反应：同一目标同帧连打 2 次，只结算 1 次。
4. 总开关关闭：零新字段、零伤害差异、零反应计数。
5. 五种技能形状（火球 / 冰环 / 雷击 / 回旋刃 / 符文雷）：真实施法后都能挂上对应附着。
6. 三种反应各自可达（冰→火、冰到期→雷、毒→火），冷却生效。
7. 燃云 3 秒 6 跳后自动消失，不残留 `state.elementClouds`。

## 7. 回滚

- 把 `ELEMENT_CONFIG.enabled` 置 false 即完全回滚（无需改代码、无需删数据）。
- 新增调试口 `__roamDebug.element.*` 只读/可控，不影响正常玩家路径。
