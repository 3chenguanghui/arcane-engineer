# P0-2 处决与破防 · 规格（先行，落码前）

> 目标：让"残血"成为一个可以主动读、主动打的战斗机会，而不是单纯把血条磨空。
> 单文件零依赖、函数级中文注释、总开关关闭时与现状逐字节同行为。

## 1. 总开关

```js
const EXECUTION_CONFIG = {
  enabled: true,
  normalThreshold: 0.15,   // 普通敌人 ≤15%
  eliteThreshold: 0.20,    // 精英 ≤20%
  bossThreshold: 0.35,     // 首领 ≤35%
  window: 4.0,             // 可处决窗口时长
  s2Cooldown: 1.2,         // 两次 S2 处决的最小间隔
  bossBreakDuration: 5.0,  // 首领破防窗口
  bossBreakDamageMul: 1.25 // 破防期间受伤倍率
};
```

- `enabled=false` 时：
  - `damageEnemy` 不调用 `executionOnHit`，伤害公式不加 `breakMul`；
  - `updateEnemies` 不推进 `execTimer/breakWindow`；
  - `drawEnemies` 不画红圈；
  - 敌人对象上**不会出现 `execTimer / breakWindow / breakUsed` 任何新字段**，
    `state.executionStats` / `state.lastExecution` 保持 `undefined`。
- 关闭后伤害、击退、顿帧、演出分级、随机数消耗全部与现在一致。

## 2. 状态机（普通 / 精英）

```
血量 > 阈值            —— 无标记
血量 ≤ 阈值（首次命中） —— 点亮"可处决"红圈（execTimer = 4s），这一发不处决
窗口内再次直接命中     —— 处决：hp 直接归零（不走额外伤害）
窗口内血量被拉回阈值上 —— 窗口作废（execTimer = 0）
4s 内没补上第二击      —— 窗口过期（expires +1），需要重新点亮
```

- **为什么"两次命中"**：一次命中就处决等于"残血自动死亡"，玩家没有读窗口的机会，
  也读不到红圈；两次命中把"点亮 → 补刀"拆成一个 4 秒的微型目标。
- 阈值偏低（15%/20%）是刻意的：处决是"补刀奖励"，不是主要输出手段。
- 处决只对**普通 / 精英**生效；`enemy.isBoss` 一律走第 3 节的破防。

## 3. 首领破防

- 血量 ≤35% 时**一次性**进入破防（`breakUsed` 阻止重复触发），持续 5s。
- 破防期间受到的伤害 ×1.25（`breakMul` 进入伤害公式，与暴击/裂印/核心暴露相乘）。
- **不冻结 AI**：首领节奏保持不变，避免"破防 5 秒变木桩"把 boss 战打散。
- 破防不是处决：不会把首领血量归零，只提供 5 秒的伤害窗口。
- 演出复用既有的 `bossBreak`（首领房 S2 白名单事件），频次由引擎 1s 节流兜底。

## 4. 演出分级与频率上限

| 事件 | kind | 档位 | 上限 |
|---|---|---|---|
| 点亮可处决 | `executionMark` | S1 | 每次点亮 1 次 |
| 处决（S2 名额可用） | `execution` | S2 | 全局 1.2s + 引擎 1s 节流 |
| 处决（S2 名额被占） | `executionLite` | S1 | 只留环 + 飘字，不闪屏不重顿帧 |
| 首领破防 | `bossBreak` | S2（仅首领房） | 一局一次 |

- `execution` 需要加入全局 `s2Kinds` 与 `ROOM_FX_PROFILE` 的
  battle / elite / survival 三档白名单；**boss 档不加**（首领不会处决）。
- 降级规则：处决本身一定有反馈（环 + 交叉斩线 + 飘字），
  只是"重演出"受预算限制——这样连杀时不会一屏闪三次。
- 设计目标：一次普通战斗房能稳定出现 2–4 次处决机会，
  精英房 1–3 次；不是稀有事件。

## 5. 与现有系统的关系

- **元素反应（P0-1）**：反应伤害带 `opts.reaction=true`，**不点亮红圈、不处决**；
  但反应造成的扣血照常推进血量，因此可能把目标推进到阈值以下——
  下一次"直接命中"才负责点亮。理由：处决是玩家瞄准打出来的，不能被被动反应白嫖。
- **地形杀**：走独立死亡路径，不进入处决判定。
- **护盾**：护盾吸收后 `enemy.hp` 才变化，阈值只看真实血量，不看护盾。
- **标签 / 融合 / 裂印 / 核心暴露 / 先手**：处决不走伤害公式（直接归零），
  这些倍率不参与；破防倍率 `breakMul` 与它们相乘，属于"窗口期收益"。
  与 P0-1 口径一致：`breakMul` **不作用于反应伤害**（反应仍取稳定的面板基数）。
- **死亡结算**：处决只把 `hp` 归零，由外层 `damageEnemy` 走唯一一次 `killEnemy`，
  不会双杀、不会重复计数。

## 6. 视觉与文字反馈（不只靠颜色）

- 可处决：头顶**旋转虚线环**（节奏感）+ **四个向内箭头**（形状语言）
  + 文字「处决」；黑白截图也能读出"这只可以打"。
- 破防：同结构换成金色 + 文字「破防」，与红色处决区分。
- 处决瞬间：两条交叉斩线 + 爆环 + 爆裂 + 飘字「处决」；S2 额外顿帧/闪屏/震屏。

## 7. 必须覆盖的验收

1. 普通敌人血量 ≤15%：首次命中点亮，第二次命中处决（hp 归零）。
2. 精英 ≤20% 生效；精英在 21% 不点亮。
3. 首领 ≤35% 进入破防、`breakUsed` 一次性、受伤 ×1.25、不处决。
4. 窗口 4s 过期后 `expires` 计数，需要重新点亮。
5. 连续两次处决：第一次 S2，1.2s 内第二次降级 S1。
6. 关闭总开关：零新字段、零处决、伤害与现在一致（含破防倍率不生效）。
7. 非直接伤害（`opts.reaction` / 无 `abilityId`）不点亮也不处决。
8. 死亡时清理 `execTimer/breakWindow/breakUsed`，不残留。
9. 标记在截图里可读（环 + 箭头 + 文字）。
10. 页面异常 0。

## 8. 回滚

- `EXECUTION_CONFIG.enabled = false` 即完全回滚，无需改代码、无需删数据。
- 新增调试口 `__roamDebug.execute.*` 只读/可控，不影响正常玩家路径。
