【二、"选过的房间还能再选"】
  改前复现（交付件 v2.2.6，tools/diag_keys_rooms.js，每条含房号/visited/cleared/fallback）：
    A  出生房          候选 1(battle,v0,c0) / 3(rest,v0,c0)
    A2 进 rest 房 3 后回出生房：进房时 visited=false、cleared=false
       → 候选又出现 1(battle) / 3(rest)          ← 走过去的房回来了（玩家报的就是这条）
    B  第一间清完      候选 3(rest) / 2(elite)
    C  只剩最后一间    候选 2(elite)
    D  全层走完        fallback=true，候选 0(start) / 3(rest) / 2(elite) 全是 visited=1，
                       标题仍是"选择下一间"        ← 第二条：回访冒充新房间
    E  首领房清完      候选为空，note "首领房已清 · 按 E 下楼"
    F  下楼后新一层    候选 1(rest) / 2(battle)
  根因：visited 没有"进房即写"的落点。逐 200ms 采样 1.4s：传送进房后 room.visited 恒为 false，
        BACKTRACK_STATS.entries 不增长（bt.currentRoomId 停在 0）；手动调 trackBacktrack 能写，
        说明函数本身没问题，是这条调用链在实测里没跑到。seen() 只看 visited / cleared，
        于是"休整/宝箱/事件"这类没有 cleared 的房，走过一次仍然回到候选。
  改法：① performRoomTeleport 提交处（state.currentRoomId 赋值同一处）直接 room.visited = true
        ② updateRoomLogic 进房块也直接写 visited（两条路径都兜住）
        ③ 回访不再伪装：标题改"全层已走完 · 以下为回访"，每张卡加"回访 · 已走过"角标
  改后同口径（同一个探针）：A2 进 rest 房后 visited=true，回出生房候选只剩 2(battle)，rest 不再出现；
        D fallback=true 且标题为"全层已走完 · 以下为回访"；E / F 与改前一致。

本版变更（v2.2.6 · 第 4 个爽感台阶：每层第 3 间房必出精英）
--------
改前实测（tools/diag_elite3.js，F1–F8 逐层生成后读数）：
  · 精英房 = 0。计划表里的精英在"本层没有精英路线"时被 applyRoomMixPlan 全部改成宝箱，
    所以实际游戏里根本没有精英房；第 3 间依次是 rest / battle / battle / chest / battle / chest / battle / battle。
改法：新增 enforceThirdRoomElite()，在房型定稿末尾把"按楼层图深度排序的第 3 间内容房"升为精英。
  · 判定口径：内容房 = 除出生房与首领房；排序 = 深度升序 + 房号升序。
  · 用换位不硬改：第 3 间若是休整/宝箱，就把它原来的房型交给一间普通战斗房，
    宝箱、休整一间不少；第 3 间若是战斗房，直接升精英（普通战斗房 4→3）。
  · 保护：若某层只有 3 间普通战斗房且第 3 间正是战斗房，则跳过不升（state.thirdRoomEliteSkipped=true），
    不让"每层至少 3 间战斗房"被跌破。
  · D2 校验放宽：精英与普通战斗房同属"战斗类"，允许同层多间（带精英路线的层会出现 2 间精英）。
    改前不加这条会在 F8 抛 "[D2] duplicate non-battle room type ... elite (rooms 3,5)"，整局打不开。
改后实测（同一探针，F1–F8）：
  第三间全部 = elite；battle=3、elite=1、combat=4、pick=1、rest=1（八层一致，房型构成未被吃掉）。
  精英房怪数 3–7（低于普通战斗房 6–11），所以经验涨幅比"3.5 倍"的账面值小。

怎么核对
--------
双击同目录的「核对版本.cmd」，它会自动算出这份文件的字节数和 MD5，
和上面的数比对，直接打印「是这一版」或「不是这一版，实际是 …」。
不用开终端，不用装任何东西。

一句话区别
----------
游戏「设置 → 关于」里写的「正文 MD5」是把版本行按占位符算出的正文指纹，
用来区分新旧；它和这里的「文件 MD5」不同属于正常现象。
核验请以本清单的「文件 MD5」为准。
