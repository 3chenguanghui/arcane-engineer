## 2. 技能卡（推荐方案 A「刻度」）

### 2.1 目标位置

在编辑器里搜这两个锚点：

- **HTML**：`function buildRewardModalHtml()` —— 里面 `state.upgradeOptions.map(...)` 拼出的
  `.reward-card` 就是卡面本体（`r-top` / `r-glyph` / `r-name` / `r-desc` / `r-result`）。
- **CSS**：搜 `.reward-card {`（紧跟着的是 `min-height: 204px` / `padding: 16px 16px 18px` / `gap: 8px`）。

注意：被动段走的是 `buildPassiveCardHtml(option, index)`，那是另一套已经改过的卡面，
**本轮不重绘、不要混进去**。只改技能段（魔法 / 科技 / 融合 / 契约）。

### 2.2 卡面结构改三处

1. **品质行**：把 `.r-rarity`（现在只有文字）换成"4 枚菱形刻度 + 文字"。
2. **数值轨**：在 `.r-result` 下面加一条三格轨道，把伤害 / 冷却 / 耗蓝从描述里拿出来。
3. **图标**：沿用现有 `rewardGlyphHtml()` 的 24×24 线稿语言，只补符文/元素图形，不引入剑盾。

### 2.3 数据从哪来（关键：这是"透传"，不是"改数值"）

`buildRewardOptions()` 里的 `pushOption` 目前只收 7 个参数，**选项对象上没有伤害/冷却**，
所以卡面拿不到数字。做法是给 `pushOption` 加一个可选的第 8 个参数，把配置里**已经存在**的字段搬过来：

```js
/* 只透传已有字段：不计算、不四舍五入、不新增默认值 */
const pushOption = (kind, id, name, glyph, desc, result, rarity, stat) => {
  pool.push({
    key: kind + ':' + id, kind, id, name, glyph, desc,
    rarity: rarity || REWARD_RARITY[kind] || 'common',
    stat: stat || null
  });
};
```

调用处按类型取数（字段都来自已有的 `MAGIC_CONFIG` / `TECH_CONFIG`）：

```js
/* 魔法：MAGIC_CONFIG 自带 damage / cooldown / cost */
pushOption('magic', magic.id, magic.name, magic.glyph, magic.desc,
  '解锁主技能 · 消耗 ' + magic.cost + ' 奥能', magic.rarity,
  { damage: magic.damage, cooldown: magic.cooldown, cost: magic.cost });

/* 科技：没有 damage，用 passive 文本 + device 的 cooldown / aether */
pushOption('tech', tech.id, tech.name, tech.glyph, tech.desc,
  '被动：' + tech.passive, tech.rarity,
  {
    damageText: tech.passive,                       // 第一格显示被动文案
    cooldown: tech.device && tech.device.cooldown,
    cost: tech.device && tech.device.aether
  });
```

**没有数字的类型要能优雅退化**：融合 / 契约卡不渲染数值轨（保留原来的 `.r-result` 一行即可），
`heal` 类魔法 `damage` 为 0，第一格显示"治疗 30"而不是"伤害 0"。
原型里的三格只是样式样例，搬进主文件时按 `option.kind` 决定显示几格。

### 2.4 HTML 片段（替换技能段那张卡的内部）

```js
/* 在 .r-top 里，把 <span class="r-rarity"> 换成刻度 + 文字 */
'<div class="r-top">'
+ '<span class="r-tag">' + (REWARD_TAGS[option.kind] || '奖励') + '</span>'
+ '<span class="r-rarity">'
+   '<span class="pips">'
+     + [0,1,2,3].map(function (i) {
+         return '<i class="' + (i < rarityRank(rarity.id) ? 'on' : '') + '"></i>';
+       }).join('')
+   + '</span>' + rarity.name
+ '</span>'
+ '<span class="r-key">' + (index + 1) + '</span>'
+ '</div>'
```

```js
/* 数值轨：放在 .r-result 之后；没有 stat 就整段不输出 */
const statHtml = option.stat
  ? '<div class="r-stats">'
    + '<div><b>' + statDamageText(option) + '</b><span>伤害</span></div>'
    + '<div><b>' + (option.stat.cooldown != null ? option.stat.cooldown.toFixed(2) : '—') + '</b><span>冷却</span></div>'
    + '<div><b>' + (option.stat.cost != null ? option.stat.cost : '—') + '</b><span>奥能</span></div>'
    + '</div>'
  : '';
```

`rarityRank()` 是一个纯展示的小函数（common=1 / rare=2 / epic=3，**第 4 档 relic 只做预留**），
不参与抽卡权重——`RARITY_CONFIG` 的 `weight` 一个都不要动。
主文件当前的 `RARITY_CONFIG` 只有 3 档；原型里那张金色「冰霜环」只是第四档的样式预留，
真实数据里不会出现，落地时不用为它加分支。

## 3. 结算面板（推荐方案 A「结论条」）

### 3.1 目标位置

- **HTML**：`function showResult()` —— 现在依次拼：`result-icon` → `modal-kicker` → `h2` →
  `modal-sub` → `result-summary`（三行结论）→ `buildReviewHtml()` → `buildTowerVoiceHtml()` →
  `buildAutobiographyHtml()` → `result-stats` → 按钮。
- **CSS**：搜 `.result-modal {`（`width: min(720px, 94vw)`），以及 `.result-stats` / `.result-stat`。

### 3.2 顺序怎么调（只挪块，不改内容）

推荐 A 的顺序是：**结论 → 三格大数（差值贴在数字下方）→ 明细 → 动作**。
落到主文件里就是把 `result-summary` 与 `result-stats` 合并成一块三格，然后接现有的
`buildReviewHtml()` / `buildAutobiographyHtml()`（这两块是叙事，保持原样、保持原顺序），最后才是按钮。

**差值的唯一合法来源**：本次运行的内存变量（比如在 `startRun()` 里把上一局的
`{ floor, kills, elapsed, crystals }` 存到一个模块级变量）。**不要**往 `state.meta` 加字段，
也不要往存档 JSON 里塞 `lastRun`。取不到上一局时：

```js
/* 没有上一局：不显示差值列，只显示历史最佳（bestFloor 是存档里已有的字段） */
const deltaHtml = prev
  ? '<span class="dlt up"><i>▲</i>+' + (state.floor - prev.floor) + '</span>'
  : '';
```

顺带把"历史最佳"角标接上已有的 `state.meta.bestFloor`，不需要新数据。

### 3.3 按钮

主 / 次按钮的层级靠**高度和填充**，不靠颜色：

```css
/* 主操作：46px 填色（沿用主文件已有的青色渐变按钮） */
.result-modal .btn[data-action="restart"] { height: 46px; font-weight: 700; }
/* 次操作：38px 描边、透明底 */
.result-modal .btn[data-action="menu"]    { height: 38px; background: rgba(255,255,255,.018); }
```

⚠️ 主文件已经有一条 `.result-modal > .btn[data-action="restart"]` 的 **`position: sticky`**
规则（为了防止重开按钮被叙事内容顶到屏幕外）。改高度时**保留 sticky**，只覆盖高度相关属性。

## 4. 动效（`ui-lab/动效.html`）

### 4.1 三个挂点

| 场景 | 挂到主文件哪里 |
|---|---|
| 卡牌入场 520ms / 错峰 70ms | `.reward-card` 的入场（弹窗打开时） |
| 结算入场 ≈1.4s | `showResult()` 渲染完成后，按 `result-icon → 标题 → 三格 → 按钮` 依次加类 |
| 按钮反馈 120 / 90ms | 现有 `.btn` 的 `transition` + `:active`，沿用 `--ease` / `--dur-fast` |
| 符文法阵 | 技能施放的表现层，纯视觉，不参与判定 |

### 4.2 参数（改节奏只改这一处）

```js
const MOTION = { cardEnter: 520, cardStagger: 70, resultCount: 700, hover: 120, press: 90 };
```

曲线沿用主文件已有的两条：`--ease`（`cubic-bezier(.2,.9,.25,1)`）和 `--ease-out`。
**不要加回弹曲线**（`back` / `elastic`）——用户明确说过不要弹跳感。

### 4.3 低配与无障碍

```css
@media (prefers-reduced-motion: reduce) {
  .reward-card, .result-modal > * { animation-duration: 1ms !important; animation-delay: 0ms !important; }
}
```

只动 `transform` / `opacity`，不动 `width / height / top / left`，避免触发布局重排。

## 5. 需要单独确认的两件事（本轮没动）

1. **武器字形**：`buildRewardOptions()` 里
   `pushOption('pact','overclock','祝福 · 锋刃协议','⚔', ...)` 的 `⚔` 是武器符号，
   和"纯魔法、不要武器"的设定冲突。建议 v1.7.0 换成符文（`✦` / `◈` 一类），
   但这属于**图标/文案层**，本文没有替你改，落地前确认一下。
2. **被动卡面**：`buildPassiveCardHtml()` 是第 31 项已经重做过的另一套卡，
   本轮三套技能卡方案不覆盖它。若要统一，需要单独排期。

## 6. 落下后怎么自检（不用改代码就能看）

1. 打开主文件，进一局，清一层，等奖励弹窗：四张卡应当**等高 224px**，
   品质刻度分别是 1 / 2 / 3 枚（普通 / 稀有 / 史诗）；第四枚金色只在原型里预留，线上不会出现。
2. 把窗口缩到手机宽度：卡面不应出现横向滚动条，数字最小 13px。
3. 主动死亡：结算页第一屏应当看到「结论 + 三个大数」，重开按钮仍然钉在底部可点。
4. 上一局不存在时，结算页不应出现空白的差值占位。
5. 存档对比：改动前后导出一份存档 JSON，字段集合必须完全一致（这是"没碰存档"的证据）。
