## 0. 现状诊断（为什么要重画）

旧背景由「随机节点 + 节点间细连线 + 星点」组成，这三点是**数据网络**的视觉语法（SaaS 官网粒子背景），
它只能读出"科技"，读不出"奥术"。而且随机连线本身就是**无秩序**——恰好用错了资源：

- 科技感来自**秩序**：同心、等分、刻度、可测量的间距、透视收敛；
- 魔法感来自**非秩序**：不闭合的弧、笔压渐变的曲线、上升、呼吸、裂缝。

因此三个方向都在做同一件事：**把"秩序结构"与"非秩序的一笔"放进同一画面**，并用配色把标题保护出来。
**金色只留给标题**：背景只用青（科技）、紫（奥术）、暖橙（余烬）、钢蓝（金属），
标题"烬"的金色渐变在整屏里是唯一的金色大色块，天然成为最亮的视觉中心。

## 1. 三个方向

### 方向一 · 符阵（**推荐**）

结构：地面透视下的巨大双层符阵。

- **真透视，不是压扁椭圆**：用简化针孔投影把地面圆环算成真实透视
  （地平线 0.30h，相机高 0.30h，焦距 1.0h，符阵中心深度 1.05h），
  近侧刻度变大、远侧刻度挤向地平线——"地面"的读感来自这个投影，不是来自变形。
- 外环半径 `rOut = clamp(0.378·(w/h), 0.42, 0.62)`（1280×800 → 0.605h；740×1030 → 0.42h，允许横向出血）。
- 三层节奏：外环 120 格刻度（每 10 格长刻度）→ 内环 72 格（每 6 格长刻度，反向）→ 内圈 3 段不闭合咒文弧（笔压两端细中间粗）
- 环外再加 2 段**不闭合大弧**（1.10·rOut），故意与内圈刻度错位，制造"非秩序"。
- 弧上 21 枚符文刻痕（6 种笔画模板随机取用），尺寸 11px、α 0.50，远看是"笔压上的小齿"。
- 中心漏光：呼吸周期 22s，峰值仅 14–19% 亮度，光学上只作"从地面漏出来"的暗示。
- 56 颗余烬从旋转的环上升起，寿命 8–17s，稀疏——这是"粒子"作为魔法而不是特效。

周期：外环 1500s（0.24°/s）· 内环 1200s（0.30°/s）· 咒文弧 1000s（0.36°/s）· 外大弧 1800s · 呼吸 22s。

### 方向二 · 余烬塔

结构：右侧三分之一，一柱上升的余烬。

- 柱心 x = 0.745w；基座 y = 0.945h；柱顶约 0.08h；柱宽随高度展开（0.55 → 2.30 倍）。
- 320 颗粒子：`off` 用三次均匀相加的类高斯分布（所以有疏密，不是均匀撒点）；
  x 位移含 `u²` 的风向偏斜（整体右倾 0.085w）+ 正弦摆动；亮度按 `sin(πu)^1.4` **先增后灭**；
  生命 8–20s，出生相位随机 → 真实的时间差。
- 颜色比例 68% 暖橙 / 22% 金 / 10% 青（青是"科技火花"）。
- 静态塔架：4 根竖骨线 + 每 0.045h 一道横档 + 右侧 26 根测量刻度（秩序，不发光）。
- 3 个"塔层环"沿光柱上浮，周期 60s，等间距——像塔的层，像在呼吸。
- 热床：椭圆刻度环 600s 旋转 + 底部软光柱（烘焙在底图上，零每帧渐变）。

周期：单颗上升 8–20s · 塔层环 60s · 气流线 130s · 热床刻度 600s · 呼吸 18s。

### 方向三 · 破碎的环

结构：画面中上部，一枚有裂口的金属环。

- 中心 (0.5w, 0.635h)，`rx = max(0.28w, 0.38·min(w,h))`，`ry = 0.52·rx`，倾角 −0.10 rad
  （比首版下移并压扁：环顶退出标题/统计/按钮带，只在中下部当"悬着的残骸"）。
- 环带内径 0.870R；缺口 0.36 rad（先画 128 段梯形环带，命中缺口即跳过）。
- 金属感来自**受光模型 + 窄高光 + 内沿暗边 + 外沿冷光**，不是灰色大块：每段颜色由 `cos(a − 3.70)` 决定
  （暗端 8/14/28 → 亮端 150/180/214），再只在高光角度贴 1–2.8px 的亮弧；副补光在右侧 0.30 rad。
- 缺口：两条断面亮切线（α 0.78）+ 青色能量团（加色，脉冲 12s）+ 缺口里的白热芯 + 沿环带向两侧渗出的 26 段能量弧。
- 12 片碎片：缺口两侧 0.62 rad 内散布，漂移周期 70s（振幅 1.4%R），自转 460–780s；
  每片画两个面（亮面 + 暗面），避免"纸片感"。
- 环外 96 根细刻度（1800s 反向）+ 两条参考圆 + 一条 70s 周期的长流线（笔压渐变）+ 浮尘。

周期：主环 1400s（0.26°/s）· 外刻度 1800s · 碎片漂移 70s · 裂隙脉冲 12s · 流线 70s。

## 2. 明度与对比度（1280×800，DPR 1，无头 Edge）

口径说明：

- **背景平均明度** = 整屏 canvas（不含 DOM 文字）采样到 160px 宽后的 RGB 均值（0–255），括号内为 WCAG 线性相对明度。
- **标题区背景明度** = 标题"烬"的包围盒外扩 26/22px 内背景的相对明度。
- **标题字明度** = 用同字号、同金色渐变离屏重绘"烬"，取 α>0.47 像素的平均相对明度。
- **对比度** = `(标题字 + 0.05) / (标题区背景 + 0.05)`。
- **比标题字更亮的格子** = 16×10 网格中，平均相对明度 > 标题字 × 0.85 的格子数（理想为 0）。

| 方向 | 背景平均明度 | 标题区背景 | 标题字 | 对比度 | 更亮格子 | 最亮格子 |
|---|---|---|---|---|---|---|
| 一 · 符阵 | **17.0 / 255（0.74%）** | 0.28% | 67.3% | **13.7 : 1** | **0** | 4.9% |
| 二 · 余烬塔 | 11.3 / 255（0.33%） | 0.24% | 67.3% | 13.8 : 1 | 0 | 1.2% |
| 三 · 破碎的环 | 13.8 / 255（0.61%） | 0.23% | 67.3% | 13.8 : 1 | 0 | 11.6% |

竖屏 740×1030：一 · 符阵平均 **20.8 / 255（1.00%）**、对比 13.8:1；三 · 破碎的环 13.0 / 255、对比 13.9:1。

结论：三个方向都满足"任何区域都不压过标题"——最亮的格子（碎环缺口的高光）也只有标题字明度的 12%，
全屏没有任何 16×10 格子接近标题亮度（更亮格子数 = 0）。符阵最亮（刻度/弧线占比大），
但标题区只有 0.28%，对比度 13.7:1 仍远高于 WCAG AAA（7:1）。

保护手段有两道：
1. **画面级**：所有亮元素都被安排在 y > 0.27h（符阵 0.48h 起、碎环 0.40h 起、余烬柱 0.10h 起且低亮度）；
2. **渲染级**：顶部 0–0.46h 有六段渐变的"文字安全罩"（0.82 → 0.68 → 0.44 → 0.22 → 0.06 → 0），每帧叠一次，动态元素也压得住。

## 3. 性能

测量环境：单实例无头 Edge（软件光栅 SwiftShader，1280×800 / 740×1030，DPR 1），
`drawFrame` 内 JS 耗时（不含浏览器合成）；稳态取 320 帧、跳过前 30 帧。

| 口径 | 首帧总计 | 其中背景自身 | 稳态每帧 均值 / p95 |
|---|---|---|---|
| 热载 1280×800（同页第二次加载） | **8.2 ms** | **6.3 ms**（贴图 3.2 + 底图 0.3 + 粒子 0.4 + 首帧绘制 2.4） | **0.75 / 1.1 ms** |
| 竖屏 740×1030 热载 | 7.2 ms | 5.2 ms | 0.80 / 1.2 ms |
| 首次冷载（浏览器首批初始化） | 94.9 ms | 13.3 ms | — |

- 首屏预算：相对现有首屏中位 1,739 ms，背景增量 **约 6.3 ms（0.36%）**，远低于 30 ms 上限。
- 首次冷载的 94.9 ms 里，约 80 ms 是浏览器首次创建画布/样式/字体的软件光栅初始化；背景自身 13.3 ms。
  冷 profile 的贴图首建在不同运行间抖动很大（3.2–48.8 ms，同一份代码热载稳定 3.2 ms），
  因此以"背景自身 6.3 ms（热载）"为交付口径，HUD 同时显示总计与自身两项，任一项超 30 ms 会标"超预算"。
- 稳态三方向（1280×800）：符阵 0.88 / 1.1 ms，余烬塔 0.78 / 1.0 ms，碎环 1.27 / 1.9 ms；
  竖屏碎环 1.66 / 3.1 ms（最重的一档，仍远低于一帧 8.3 ms 的 120Hz 预算）。
  无头环境无垂直同步，帧率 83–120，因此绘制不构成瓶颈，真实 GPU 只会更低。
- 成本控制手段：6 色"软光"预烘焙进**一张 384×64 光斑图集**（只建 1 个 canvas，避免逐张首建税，不用 `shadowBlur`）；
  底图（渐变/暗角/颗粒/塔架）只烘焙一次，每帧一次 `drawImage`；
  颗粒用 112px tile 平铺，成本与分辨率无关；可变笔画宽度的弧按段绘制，没有逐帧建渐变。

可调开关：`?dir=1|2|3`、`?motion=0`（静帧）、`?ui=0`（隐藏文字层与指标），键盘 `1/2/3`、`P` 暂停、`H` 隐藏文字、`M` 收起指标。

## 4. 动效周期与"10 秒静看"判据

| 元素 | 周期 | 10 秒位移 | 判读 |
|---|---|---|---|
| 符阵外环刻度 | 1500s | 2.4°（刻度间距 3°） | 不足一格 |
| 符阵内环刻度 | 1200s | 3.0°（刻度间距 5°） | 0.6 格 |
| 符阵咒文弧 | 1000s | 3.6°（段宽 2.5°） | 约 1.4 段，笔画柔和 |
| 符阵外大弧 | 1800s | 2.0° | 不足一格 |
| 中心呼吸 | 22s | 亮度 ±5% | 只读到"呼吸"，读不到"移动" |
| 余烬塔塔层环 | 60s | 上浮 0.13h | 线宽 1.2px、α ≤ 0.17，几乎察觉不到 |
| 碎环主环 | 1400s | 2.6° | 不足一圈刻度的 1/4 |
| 碎环碎片 | 70s | 位移 ≤ 1.4%R | 数 px |
| 裂隙脉冲 | 12s | 亮度 ±14% | 呼吸 |

说明：结构件（环、刻度、网格）10 秒内位移都在"约一格"以内，静看读作静止；
余烬/气流/浮尘这类"生命"元素本身就在动（否则背景会死），但它们只占画面极小面积（< 2%），
可以通过 `?motion=0` 或系统 `prefers-reduced-motion` 直接冻结为静帧（默认即遵守该系统设置）。

## 5. 与主文件的接入建议（本轮不落盘）

1. 新增 `#titleBg` canvas，`position:fixed; inset:0; z-index:0`，标题层整体抬到 `z-index:2`；
2. 首帧同步绘制一次（在标题淡入动画开始前），此后只在标题页可见时 `requestAnimationFrame`；
3. 进入游戏后 `cancelAnimationFrame` 并释放 canvas（标题页背景不应继续吃帧）；
4. `dpr = min(devicePixelRatio, 1.5)`，`resize` 去抖 150ms 重建底图；
5. 保留 `?bg=off` 兜底开关；若首帧实测 > 30 ms，自动降级为静帧（`?motion=0` 的同一条路径）。

## 6. 已知限制 / 剩余风险

- 标题页 mock 的版式（统计胶囊、两个按钮、难度卡、工具条）是按现有信息密度复刻的判读参照，
  并非主文件真实 DOM；移植时明度与对比度需在主文件上复测一次。
- 碎环方向在竖屏下体积最大（横向约 80% 屏宽），墙面般的暗色环体对画面压迫感最强，属"最张扬"的方案；
  **首选仍是方向一（符阵）**：科技（刻度/等分/透视）与魔法（断弧/符文/余烬）各占一半，且横向出血可控。
- 明度采样每 2 s 一次（160px 宽小图回读），只用于实验台读数，移植时不应保留该回读逻辑。
- 无头软件光栅下首次冷载的 67–153 ms 波动来自画布首建与字体首绘，不作为性能基准；
  验收以"热载 8.2 ms / 背景自身 6.3 ms / 稳态 0.75 ms"为准。
